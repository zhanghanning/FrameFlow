# 架构与业务规则

## 工程组织

```text
JavaWebSQL/
  backend/       Spring Boot 应用，按业务分包
  frontend/      Vue 单页面应用
  database/      表、视图、过程、触发器、演示数据和性能实验
  scripts/       环境初始化、启动、停止和验证
  docs/          开发记录、接口契约和部署说明
  uploads/       本地素材文件，运行时产生
```

前端通过 `/api` 调用后端。开发时 Vite 转发到 8080；MySQL 3306 仅供本机应用连接。后端按 Controller 接收请求、Service 执行业务事务、Mapper 执行明确 SQL 的层次组织。

## 关键规则

- 金额用 DECIMAL / BigDecimal，结算参与方金额取人民币分，工作室份额承接尾差，所有份额总和等于可分配金额。
- 平台账号和外部来源编号共同标识一条收益，CSV 先预览再落库。
- 作品与发布分开：同一成品可以对应多个平台发布。
- 协议激活时核对比例总和与日期范围；同项目的有效协议期间不重叠。
- 正常收入按归属日期关联协议，退款继承原收入的协议；已确认收入在结算前保持固定。
- 结算草稿建立收入和成本的唯一分配关系，生成时保存比例与金额快照。
- 已审核结算保持稳定，通过后续调整记录反映新增退款。
- 审核人与提交人分开。付款登记依据已审核余额，付款和审核分别记录。
- 财务统计先分别聚合收入与成本，再合并，避免一对多 JOIN 导致金额重复。
- 素材记录保留引用关系；项目通过 project_asset 获得使用授权，发布时同时验证授权时间与目标平台。
- 注册创建个人创作者；其他岗位申请由管理员审批追加。项目负责人和成员决定生产范围，财务/审核读取与生产写入分别判断。

## 数据库职责

数据库负责关系完整性、唯一来源、金额约束、结算生成、状态历史和已审核记录稳定性。Java 负责权限、业务入口、事务边界、文件存储、CSV 解析与交互数据组织。视图集中表达项目收支、创作者余额和授权到期查询。

性能实验使用独立 perf_revenue 表。使用同一筛选条件比较增加组合索引前后的执行计划和实测耗时，实验数据不会加入工作室看板。
