## Database objects
views v_project_finance (aggregate revenue and cost independently before joining), v_creator_balance (approved lines minus payments), v_asset_license_expiry.
Shared calculation: sp_calculate_settlement(p_settlement_id,p_contract_id,p_start,p_end,p_actor). It recalculates a DRAFT in place; generation calls it after creating the row. Edit/recalculate/cancel use a READ_COMMITTED Java transaction, locking old/new contracts in ID order then the settlement and rechecking its contract before changes. Snapshot and allocations share this transaction.
procedure sp_generate_settlement(IN p_contract_id BIGINT,IN p_start DATE,IN p_end DATE,IN p_actor BIGINT,OUT p_settlement_id BIGINT). Caller owns transaction. Lock contract row serializes generation; select eligible unassigned revenues/costs; refuse empty selection; sum and snapshot; participant amounts ROUND(basis*rate/100,2), studio residual basis-SUM(participants). Negative basis allowed for refund carry. UNIQUE settlement allocations prevent double settlement. SQL exception SIGNAL business error. Backend calls MyBatis statementType CALLABLE with OUT.
trigger settlement status history, actor chosen from submitted_by/approved_by/created_by; guard approved settlement amounts/status; revenue and cost freeze once allocated; contract participants immutability once ACTIVE. Keep trigger responsibilities small and explainable.

## Asset media previews

Ubuntu 22.04 uses FFmpeg and ffprobe from the official apt repository. Both executables must be available on the backend process PATH. Install with `sudo apt update` followed by `sudo apt install -y ffmpeg`; current verified version is 4.4.2. The optional `python3 scripts/create_demo_video.py` generates `.runtime/media-demo/forest-light.mp4` for manual upload and also requires `sudo apt install -y python3-pil fonts-dejavu-core`. Existing SVG initialization remains `python3 scripts/create_demo_assets.py` before database initialization.

All routes below have the `/api` prefix and use the existing Bearer session. Each request calls `studio.assetAccess` before accessing source files or cached derivatives; project authorization changes apply to cached previews too. Media metadata, derivatives and the original file respond with `Cache-Control: private, no-store`.

| Endpoint | Response |
| --- | --- |
| `GET /assets/{id}/media` | Standard API envelope with `{type,mimeType,durationSeconds,posterUrl,previewUrl}`. `type` is VIDEO/IMAGE/AUDIO/DOCUMENT; `mimeType` describes the original file. |
| `GET /assets/{id}/poster` | Video JPEG cover, `image/jpeg`. |
| `GET /assets/{id}/preview` | Video preview, `video/mp4`. |
| `GET /assets/{id}/file` | Original file with its original media type and download filename. Used for full playback and downloads. |

VIDEO metadata returns original duration in seconds and API-relative URLs `/assets/{id}/poster` and `/assets/{id}/preview`. IMAGE returns `/assets/{id}/file` as posterUrl; its duration and previewUrl are null. AUDIO/DOCUMENT return null duration and both URLs null. Non-video requests to poster/preview return 400.

`AssetMediaService` generates a JPEG cover and a 3-second silent looping preview: H.264/yuv420p MP4 with faststart, 30 fps, maximum 640px on either side, original aspect ratio retained. Videos shorter than 3 seconds loop to fill the preview. The first 3.15 seconds supply a 3-second sequence with a 150ms crossfade across the loop seam. ffprobe verifies output duration. The original file is retained unchanged.

New video uploads generate derivatives within the upload transaction; invalid or undecodable video returns a clear error and rolls back the asset record while removing the attempted upload and derivatives. Existing videos generate derivatives on their first media request. A temporary directory receives the cover, preview and metadata; only a complete directory is atomically published as `UPLOAD_DIR/previews/{id}/`. Cache reads proceed without the generation lock, while generation is serialized with a second cache check inside the lock. Commands use ProcessBuilder argument arrays, with bounded process timeouts and encoding thread counts. Generation errors are returned for retry rather than replaced by placeholder video.

The Vue material cards load real poster images. Pointer hover or keyboard focus lasting 800ms opens an enlarged preview beside the card; videos then fetch the lightweight clip and play muted on a loop. The enlarged card fades in/out; reduced-motion preference keeps it static. Clicking opens a centered full-material dialog and fetches the original file for image display or controlled video/audio playback. Closing or leaving the preview aborts pending requests, stops playback and releases blob URLs. Documents provide original download and detail actions.

With the independent test backend running via `bash scripts/test_backend.sh` in another terminal, run `python3 scripts/verify_media.py` from the project root. It uses `http://localhost:8082/api` and `frameflow_test`. All 6 groups passed; recorded results are in `docs/media-verification.json`: real JPEG cover and silent H.264 preview with unchanged original, authentication/project authorization and immediate cached-preview revocation, short portrait video looping with aspect ratio retained, static image behavior, invalid-video upload rollback, and completed cache reads while another thread holds the generation lock. The concurrency check uses the compiled AssetMediaService with CountDownLatch-controlled ordering; it checks completion before releasing the lock, without comparing encoding speed. The recorded preview is 3.0 seconds and 76324 bytes, from a 3345446-byte source.
